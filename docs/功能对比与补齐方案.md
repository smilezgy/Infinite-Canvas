# Infinite-Canvas 功能对比与补齐方案

> 分析对象：本项目（Infinite-Canvas v2026.08.04）
> 对照项目：InvokeAI、SwarmUI、ComfyUI、Stable Diffusion WebUI (A1111)、Open WebUI
> 日期：2026-11-04

---

## 一、本项目现状盘点

### 页面（13 个）

| 页面 | 定位 |
|---|---|
| `index.html` | AI Studio 主框架，iframe 切换各模块 |
| `canvas-list.html` | 项目工作台（项目 / 画布 / 回收站） |
| `canvas.html` | 无限画布（节点式，核心） |
| `smart-canvas.html` | 智能画布（另一套节点体系） |
| `asset-manager.html` | 素材库（分类 / 裁剪 / 打标） |
| `online.html` | 在线生图（多供应商） |
| `gpt-chat.html` | GPT 对话 |
| `zimage.html` / `enhance.html` / `klein.html` / `angle.html` | 各模型专属控制台 |
| `api-settings.html` | 多供应商 API 配置 |
| `comfyui-settings.html` | ComfyUI 实例与工作流 |

### 后端能力（130+ 路由）

- **多协议供应商适配**：OpenAI 协议 / Gemini / 方舟 / APIMart 异步协议，供应商可增删改、拉取模型、连通性探测
- **多引擎接入**：本地 ComfyUI（多实例 + 负载选择）、RunningHub 工作流、ModelScope、即梦 CLI、Midjourney
- **生成类型**：文生图 / 图生图 / 视频 / LLM 对话（含流式 SSE、Agent）
- **资产体系**：素材库（库-分类-条目三级）、提示词库、本地素材、共享文件夹
- **画布体系**：项目 / 画布 / 会话持久化、画布回收站（30 天）、工作流导入导出
- **基础设施**：存储目录可配、i18n、明暗主题、版本检测与回滚、队列状态接口

### 已具备但**未被利用**的数据

`history.json` 每条记录已含：

```
prompt / images / image_items / timestamp / type / model /
provider_id / provider_name / task_id / params / raw_usage(total_tokens…)
```

这些字段足以支撑「用量统计、成本分析、跨页面统一检索」，但目前**只在各自页面内被局部读取**，没有任何聚合视图。

## 二、同类项目功能对照

### 2.1 各项目核心功能

| 项目 | 核心功能 | 值得借鉴的逻辑 |
|---|---|---|
| **InvokeAI** | Unified Canvas、Gallery、**Queue**、Model Manager、Workflow Editor、Recall Parameters | Gallery 是**全局产出中心**：所有生成结果统一入库，可按元数据检索、收藏、复用参数；Queue 面板实时展示排队/运行/取消 |
| **SwarmUI** | 多后端、**Image History**、**Grid Generator**、Image Batch Tool、wildcard/preset 自动补全 | Grid Generator = 参数矩阵批量出图（种子/步数/提示词变体组合）；历史以网格呈现，支持按会话分组 |
| **ComfyUI** | 节点工作流、**队列**、自定义节点生态、模型管理、API | 队列是显式可观测对象：pending / running / done，可中断 |
| **A1111 WebUI** | txt2img / img2img / inpaint / 高清修复、**XY Plot**、**Prompt Matrix**、Interrogate 反推、批量、**PNG Info 参数复用** | 出图后能从图片反读全部参数并一键回填，形成"试错闭环" |
| **Open WebUI** | 对话 + 生图、多用户 / RBAC、知识库 | 用户隔离与配额（本地单人工具可暂不需要） |

### 2.2 归纳出的**共同功能与共同逻辑**

1. **统一产出中心**（Gallery / History）
   所有引擎、所有页面的产物汇入同一处，支持缩略图浏览、筛选、搜索、收藏。
2. **元数据与参数复用**（PNG Info / Recall Parameters）
   每条产出携带完整生成参数，可反读、可回填，避免重复调参。
3. **任务队列可观测**（Queue Panel）
   排队位置、运行状态、耗时、中断能力。
4. **提示词资产化**（Prompt Library / Wildcards / Presets）
   提示词库、预设、通配符，跨会话复用。
5. **多后端抽象层**（Provider / Backend Adapter）
   统一接口对接本地与云端引擎，前端不感知差异。
6. **参数矩阵批量**（XY Plot / Grid Generator）
   一次提交多组参数，网格化对比结果。
7. **本地优先 + 目录可配 + 数据可迁移**（模型库 / 输出目录设置）
8. **明暗主题 + 多语言 + 快捷键**

## 三、差距分析

| 共同能力 | 本项目 | 结论 |
|---|---|---|
| 统一产出中心 | ❌ 每个生成页各有一套历史面板，互不相通 | **需补齐（最高优先级）** |
| 元数据 / 参数复用 | 🟡 数据齐全，但只能"看"，不能统一检索、不能收藏 | **需补齐** |
| 收藏 / 评分 | ❌ 全项目 0 处实现 | **需补齐** |
| 用量统计 | ❌ 有 `raw_usage` 却无任何统计视图 | **需补齐** |
| 任务队列可观测 | 🟡 后端有 `QUEUE` + `/api/queue_status`，前端 0 处展示 | **需补齐（轻量）** |
| 提示词资产化 | ✅ 提示词库（库-分类-条目） | 已达标 |
| 多后端抽象 | ✅ 供应商 + ComfyUI 实例 + 多引擎 | 已达标，优于多数同类 |
| 参数矩阵批量 | ❌ 无 XY Plot 类能力 | 可延后（画布工作流可部分替代） |
| ControlNet | ❌ 0 处 | 依赖具体引擎，非通用缺口 |
| 主题 / i18n / 目录可配 | ✅ | 已达标 |

### 结论

本项目在「引擎接入广度」和「画布交互」上明显强于同类，**短板集中在"产出之后"的管理环节**：
生成完的图散落在各页面历史里，无法统一检索、无法标记、无法统计用量。

这正好是 InvokeAI Gallery、SwarmUI Image History、A1111 历史页共同解决的那一块。

## 四、补齐方案：任务中心（Task Center）

### 4.1 设计目标

一个页面统一解决「统一产出中心 + 收藏评分 + 用量统计 + 运行态可见」，不新增依赖、不改动现有页面逻辑、不破坏 `history.json` 结构。

### 4.2 页面结构 `static/task-center.html`

**标签一：概览**
- 统计卡片：总产出、今日生成、近 7 天、图片总数、收藏数、Token 总量
- 近 14 天生成趋势柱状图（纯 CSS/Canvas，无第三方图表库）
- 按类型 / 供应商 / 模型 Top 分布
- 「正在运行」区块：读取本地 ComfyUI 队列，显示类型、提示词摘要、已运行时长

**标签二：任务**
- 统一列表（跨 zimage / online / klein / angle / enhance / canvas 等全部来源）
- 筛选：关键词、类型、供应商、仅看收藏、时间范围
- 排序：最新 / 最旧 / 评分
- 操作：收藏、星级评分、复制提示词、复制参数 JSON、查看原图、删除
- 批量：全选、批量收藏、批量删除

### 4.3 后端接口（`main.py`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/tasks` | 统一任务列表，支持筛选/分页/排序 |
| GET | `/api/stats/overview` | 用量聚合统计 |
| POST | `/api/tasks/favorite` | 切换收藏 |
| POST | `/api/tasks/rating` | 设置星级 |
| POST | `/api/tasks/delete` | 批量删除 |
| GET | `/api/queue/detail` | 运行中任务明细 |

### 4.4 存储设计

- **不修改** `history.json`（避免破坏现有页面读取）
- 新增 `data/task_meta.json` 旁挂元数据：

```json
{
  "<timestamp>|<task_id>": { "favorite": true, "rating": 5 }
}
```

- 任务 key 由 `时间戳(3位小数) + task_id 或首图文件名` 组成，稳定可复现
- 写入采用「临时文件 + `os.replace`」原子替换，避免写坏

### 4.5 顺带完成的优化

1. 给本地 ComfyUI 队列项补充 `type / workflow / prompt / started_at` 字段，使运行态可读（原来只有 `task_id` + `client_id`）
2. 队列任务结束仍在 `finally` 中移除，不改变原有并发行为
3. 新页面沿用项目既有 `theme.css`、`theme.js`、`lucide`、`touch-mouse.js`，与主框架风格一致

### 4.6 暂不实施（并说明原因）

| 功能 | 原因 |
|---|---|
| XY Plot / 参数矩阵 | 需改动生成链路与并发模型，收益低于任务中心，建议单独立项 |
| ControlNet | 强依赖具体推理引擎（ComfyUI 节点 / 供应商是否支持），不属于通用能力 |
| 多用户 / RBAC | 本项目定位本地单人工具，引入会显著增加复杂度 |

| 项 | 结果 |

### 5.5 设计上的取舍

1. **旁挂元数据而非改 `history.json`**
   收藏/评分存在 `data/task_meta.json`，key 由「时间戳 + task_id/首图名」构成。
   这样原有各页面的历史读取逻辑零改动，也不会因新字段引发兼容问题。
2. **删除只移除历史，不动文件**
   符合项目一贯的数据安全取向，UI 上明确提示「图片文件不会被删除」。
3. **运行队列如实呈现**
   本项目的 `QUEUE` 仅用于状态展示（非并发控制），且只有本地 ComfyUI 走这条链路，
   因此 UI 标注为「本地 ComfyUI 队列」，未提供虚假的「取消任务」按钮。
4. **不引入图表库**
   趋势图用纯 CSS 柱状实现，避免为一张图增加体积与离线依赖。
